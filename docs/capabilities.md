# Pebble Inspect capability audit

Audited 2026-10-21 for **Core Devices Pebble Time 2**, watchapp platform `emery`, firmware board `obelix`, SiFli SF32LB52. This is the current shipping Core Devices watch, not the historical unreleased Pebble Technology Time 2. [Board configuration][board] and the [official firmware overview](https://developer.repebble.com/pebbleos/) establish that mapping. Opening Inspect replaces the foreground watchface; observations made inside Inspect cannot be attributed to the watchface that was running before it.

## Evidence and limits

The inspected firmware source is [`coredevices/PebbleOS` commit `5cf6c353bad2903e0a789b27bce278f54317b267`](https://github.com/coredevices/PebbleOS/commit/5cf6c353bad2903e0a789b27bce278f54317b267), committed 2026-10-20. It was shallow-cloned into `/tmp/pebble-inspect-PebbleOS-audit`, outside this application repository. This audit neither modifies firmware nor flashes a watch. The installed watch's exact firmware build has not been established; inspecting current source does not prove that every internal feature ships in that build.

The released app SDK was checked separately: **4.33.1**, installed at `/home/ubuntu/.local/share/pebble-sdk/SDKs/4.33.1/sdk-core/pebble/emery/`. The generated `include/pebble.h` SHA-256 is `2c801c32d77fab70f576482afb21586deba256fbda90a3528f6b02fbe3025548`. Its declarations, `pebble_sdk_version.h` macros, and `nm -g --defined-only lib/libpebble.a` were checked against the source [export whitelist][exports]. Battery, connection, heap and WatchInfo functions are present. PFS, kernel heap, thread statistics, reset reason and OS uptime functions listed below are absent from that released app interface. Finding an internal header or a symbol in firmware does not make it callable by a watchapp.

The [official documentation index](https://developer.repebble.com/llms.txt), [firmware overview](https://developer.repebble.com/pebbleos/), and [SDK export guide](https://developer.repebble.com/pebbleos/docs/development/sdk_export/) were consulted. The firmware documentation follows `main`; generated app headers describe the installed SDK release. The source and released SDK take precedence over assumptions based on older Pebble firmware.

**Classification:** *reported* is a value returned by the OS, including its own modeling or quantization; *measured* means actual observed events/counters; *derived* is arithmetic over valid observations; *estimated* needs explicit modeling assumptions; *unavailable* means the stock watchapp cannot obtain that scope. No battery percentage is presented as a laboratory measurement of remaining energy.

The ranks below are user value when diagnosing battery drain or general health, not implementation order. All public APIs named here were verified in SDK 4.33.1. Their earliest marketing firmware/SDK version is **not established** in this audit; source ABI revisions are listed separately and must not be mistaken for marketing versions. Minimum custom firmware versions for proposed exports are **not established** because none has been implemented or released.

## ABI and release verification

Connection events are **debounced by firmware**, not raw radio transitions.
The [inspected service](https://github.com/coredevices/PebbleOS/blob/5cf6c353bad2903e0a789b27bce278f54317b267/fw/services/debounced_connection_service/service.c#L18-L109)
hides disconnections that recover within its 25-second interval. The public
peek and subscription wrappers use that filtered state. Thus Inspect's drop
count can omit brief physical outages, and its durations measure the reported
state. The precise delay on an unverified physical firmware build is not
established merely by inspecting this revision.

The pinned whitelist records these `addedRevision` values: battery peek **0**, connection peeks **66**, heap used/free **17**, WatchInfo calls **22**, own worker state **16**, `persist_get_size` **0**, `persist_get_max_size` **99**, `wakeup_query` **24**. The [process-info ledger][abi-ledger] maps ABI revisions to internal app-SDK minor numbers; there is no safe arithmetic conversion to release numbers. “Verified in SDK 4.33.1” is the established compatibility statement here, not “first introduced in 4.33.1.”

Watch identity is available through `watch_info_get_model()`, `watch_info_get_firmware_version()` and `watch_info_get_color()`. The [implementation][watch-info] explicitly distinguishes `WATCH_INFO_MODEL_COREDEVICES_PT2` from legacy `WATCH_INFO_MODEL_PEBBLE_TIME_2`. The three-number public firmware version is not a source SHA or a full signed build identity. Recovery version, bootloader, hardware serial and Bluetooth address in firmware's built-in Information view are not implied public WatchInfo fields.

The SDK export guide describes wrappers, syscalls, whitelist registration and SDK-revision bumps. Its displayed macro/path examples may lag current source: the pinned tree uses `PBL_SYSCALL`, as seen in [WatchInfo][watch-info], so follow that revision's syscall implementation rather than copying an obsolete `DEFINE_SYSCALL` example. New exports require a matching firmware **and** SDK release. `PBL_API_EXISTS()` is a compile-time SDK test; it cannot discover a missing firmware trampoline safely at runtime. See the [firmware roadmap](firmware-roadmap.md) for separate stock and experimental targets.

## v0.1 honesty rules

In v0.1.1, Inspect Memory derives **heap total bytes = used + free** and
**used percent = 100 × used / total**, rounded to one decimal place. Display
sizes use KiB (1 KiB = 1024 bytes), rounded to one decimal, with exact used/free
bytes available below. A zero or overflowing total yields unavailable percentage
and total, never a fabricated 0% value. This denominator is Inspect's heap,
not watch-wide RAM or the SDK's entire app code/static-data budget.

- Label history as **foreground observations** and distinguish each launch/session. A stored last value is a past sample, not evidence for the closed interval. Initial peeks establish a baseline and do not count as connect/disconnect events.
- Keep phone-app and PebbleKit state separate. Count actual callbacks/transitions within a valid interval; do not turn unknown time into connected or disconnected time. Handle clock moves, long gaps and charging changes before any future rates or durations.
- Present percent as the OS reports it. No smoothing, interpolated missing data, app energy ranking or inferred reset count appears in v0.1. Remaining runtime is an explicitly **estimated** extrapolation from foreground observations, with the rules below.
- Label heap **Inspect only**. Loading UI, sampling and persistence are part of the observing app's resource use. The watchface is no longer foreground while Inspect is open.
- Unsupported system metrics say **requires firmware support** or are documented as unavailable. Zero is a valid measurement, never an encoding for unsupported or unreadable.

## v0.1 remaining-runtime estimate

The [implementation](../src/c/model.c) computes `remaining_seconds = current_percent × observed_span_seconds / drop_percentage_points`. This is a rough linear projection of whole-watch battery behavior while Inspect runs, assuming similar future use. It is neither a promised battery life nor a measurement of the previous watchface's consumption.

A result requires at least **three distinct observation timestamps**, at least **two hours** of observed span and at least **three percentage points** of monotonic drop in the same uninterrupted, unplugged foreground segment. Duplicate timestamps do not inflate the sample count. Charging/plugging, percentage rises, session changes, time reversals and gaps over **300 seconds** invalidate/reset the evidence segment. Results are unavailable while charging/plugged, when observation is inactive, when the last observation is over **300 seconds** old, or when the clock precedes it. Projections over **30 days** are rejected rather than clipped to an apparently credible value. Insufficient evidence remains insufficient, including the common case where ordinary brief visits to Inspect never accumulate two hours.

Display the observed span, drop and sample count with the result and the assumption of similar future use. This projection does not justify filling closed intervals, computing per-app energy, or attributing drain to the watchface replaced when Inspect opened.
